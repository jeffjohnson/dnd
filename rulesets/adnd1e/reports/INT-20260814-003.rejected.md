## Tooling note

The unresolved-endpoint condition is caught by the applier inside the
transaction, which rolls back correctly but aborts on the *first* bad endpoint.
The nine rows listed above were therefore enumerated with a standalone probe
against the same registry the applier uses, not by nine successive rejections.

Promoting that enumeration to a pre-snapshot precondition was attempted and
withdrawn. It has to be measured against the real node registry, and the shared
rewind fixture used by the integrator tests presents a registry with
cross-bundle registrations stripped — a state production never produces — so the
check reported false positives there. Landing it meant either weakening the check
or reworking that fixture, and neither is worth trading for what is only a
reporting improvement; the safety property is already enforced. The enumeration
helper is retained for reporting use.
